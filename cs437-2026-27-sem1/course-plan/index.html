CS437 Course Plan

Semester I, 2026-27

Course Plan

A lab course on building software with AI-assisted workflows. This page lists the topics the course plans to cover, week by week.

Subject to change

This is the first offering of CS437. The topics below indicate what we intend to cover. The sequence, pace, and emphasis may change during the semester. Assessment details will be announced in class.

Objective

Each student works in a small team on a single project throughout the semester. The final assessment is practical: a person who cannot program requests a new feature in plain English, the team's system implements it, and the team's own test suite determines whether it is accepted.

Format

A lab-only course, conducted hands-on, in two 90-minute sessions each week. It is open to students of all years and backgrounds. The entry requirement is the ability to describe clearly what you want built.

Phase 1 — Foundations

Wk 1

Git and GitHub

Version control performed manually, then with an agent: branches, commits, pull requests, reviewing changes, and resolving conflicts.

Wk 2

Model, agent, and harness

The components of an AI coding agent, a brief history of language models, and building a minimal agent from first principles.

Wk 3

Specifications and prompting

Writing specifications an agent can execute, and the difference between an unstructured request and a specification with acceptance tests.

Wk 4

Agentic development workflow and guardrails

A disciplined workflow from request to pull request to deployment, and measures that prevent an agent from making unintended changes.

Phase 2 — Prototyping and scaling

Wk 5

Full-stack application from a specification

Implementing a running application from a written specification. A web application with an API is the recommended form.

Wk 6

Providing context to the agent

Supplying an agent with the context it needs through conventions files, skills, memory, and MCP servers.

Wk 7

Working in code you did not write

Adding features to an unfamiliar codebase and reviewing large machine-generated changes, including using one agent to review another agent's work.

Wk 8

Stress-testing and profiling

The difference between a prototype and a production system: measuring behavior under load and identifying performance bottlenecks.

Phase 3 — Security, testing, and architecture

Wk 9

Security auditing

Common vulnerabilities in AI-generated code, prompt injection, and scanning and auditing a project for security issues.

Wk 10

Tests and the verification gate

Defining correctness through a test suite, measuring coverage, and writing tests that agents cannot silently modify.

Wk 11

Architecture and hardening

Evaluating the structure an agent has produced, deciding when to refactor rather than regenerate, and resolving outstanding security findings.

Phase 4 — Capstone

Wk 12

Acceptance run and demonstrations

A feature requested in plain English by someone outside the team, implemented by the team's system and evaluated by its verification suite, followed by demonstrations and a team review.
