Prompt Golf

Yesterday the rule was "explain, don't drive." Today it flips: the AI writes the code, and your skill is the prompt. But there's a catch — every token counts. You prompt an AI to write a small function, and your score is the number of tokens in your prompt plus the AI's code. Lowest score wins. Fewer tokens means less to pay for and less context to manage, which is a real thing you will care about all semester.

Everyone uses the same model

So the leaderboard is fair, every group prompts the same model:

google/gemma-4-26b-a4b-it:free   (on OpenRouter)

Use it through your agent-lab harness, or open openrouter.ai/chat and pick that model — it's free, no key needed for the chat. It's a small model on purpose: it rewards a precise prompt and punishes a sloppy one, which is the whole game. (It's also a preview of next week — small models have weak spots, and you'll go hunting for them.)

The score counts your prompt and the code — not the model's hidden "thinking." That keeps it simple and fair. In the real world your bill also includes the model's reasoning tokens, which is why picking the right model for a job is its own skill. We use a small non-reasoning model here, so what you see is basically what you'd pay.

How a hole works

  1. Read the challenge. Write a prompt and save it as prompt.txt.
  2. Paste your prompt into the model above and save the code it gives back as solution.py (just the function, nothing else).
  3. Score it: 
    python score.py 1 prompt.txt solution.py
    It runs the hidden tests and, only if they all pass, prints your token score.
  4. Report your group's score for each hole to the scoreboard on screen. Lowest total across the holes wins.

score.py does not call an AI. It only counts the tokens in your two files and checks the code against the tests — you generate the code with the model, then score the result. Don't sit waiting for the script to write code; it won't.

Grab the scorer once and reuse it for every hole: Download score.py. It counts tokens the same way for everyone, so groups are comparable. Precise wording shortens the prompt; a tidy function shortens the code — both lower your score.

Hole 1 — Reverse

Write rev(s) that returns the string s reversed.

rev("hello")  ==  "olleh"
rev("ab cd")  ==  "dc ba"
rev("")       ==  ""

The warm-up. See how few tokens a working prompt can be.

Hole 2 — Top word

Write top_word(text) that returns the most frequent word. Split on whitespace, compare in lowercase, and if two words tie, return the one that appears first.

top_word("the cat the dog")    ==  "the"
top_word("a b b a")            ==  "a"      # tie 2-2, "a" appears first
top_word("Hello hello WORLD")  ==  "hello"  # lowercased

Here a vague prompt fails the tests — the tie rule and the lowercasing have to be said. Precision is the game.

Hole 3 — Line stats

Write line_stats(path) that reads the text file at path and returns a tuple (number_of_lines, total_words, longest_line_length). Count lines with splitlines() (a trailing newline does not add an empty line).

# a file containing:
# hello world
# foo
# <blank line>
# longest line here now
line_stats(path)  ==  (4, 7, 21)

The biggest task — reading, then computing.

Chain bonus. Solve this one through your agent instead of by hand: give it a read_file tool and a compute tool, and make it call both in a single turn — read the file, then compute the stats. Show the two tool calls to an instructor for a bonus. If you have never chained two tool calls, this is the rung from Class 05 — sit with a group-mate who has.

Hole 4 — Parse a config (bonus, harder)

For groups that clear the first three. Write parse_config(text) that turns config text into a dictionary. Each line is key: value. Skip blank lines and lines starting with #. Strip whitespace around the key and value. Split on the first colon only. If the value is all digits, store it as an int; otherwise keep it a string.

parse_config("# config\nname: Ada\nage: 36\n\ncity: London")
  ==  {"name": "Ada", "age": 36, "city": "London"}

parse_config("url: http://a.com:80")
  ==  {"url": "http://a.com:80"}   # only the first colon splits

More rules to convey means more room to be wordy or tight — the token spread here is the widest of the four. This is where a precise prompt really pays.

Finished the holes? Take on colf.dev

The stretch round. colf.dev is the polished version of this exact game — prompt an AI to solve a challenge, scored on prompt tokens plus code tokens, on a global leaderboard. Same idea as ours, but the problems are real algorithms (LRU cache, Dijkstra, N-queens) and the AI is built into the site.

  1. Open colf.dev, sign in, and pick a challenge (start with LRU Cache).
  2. Write the shortest prompt that makes it produce the required function, click Generate code, then Run tests.
  3. Get it passing, then fight to shrink your token total — and see where you land on the global board.

Compare notes as a group: what wording shaved the most tokens? The best players here beat the top of the leaderboard with prompts shorter than a single sentence.

The rule for AI today: the AI drives, you steer

Opposite of yesterday. You may have the AI write the whole function — that is the point. What you may not do is hand-write the code and pretend it was prompted, or count tokens by hand. Submit the real prompt you used and the real answer you got, and let score.py count. The honest game is the fun one.
