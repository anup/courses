The entry bar

If you can describe what you want in plain English, you can begin.

Teams mix levels

No one is left alone at their level.

Build what I describe

Teams of three or four — then pair up with another team.

Behind a folder, build a secret layout of five cards: some upright, some sideways, some overlapping, red and black mixed.

Your builder is one person from the other team. They can't see your layout and can't ask questions — they build only from your written words. Just like an AI.

Write the spec — then check the build

  1. Write instructions to recreate your layout. Words only — no pointing, no pictures.
  2. Hand it over. Their builder makes it, confidently guessing wherever your words run out.
  3. Drop the folder. Put your layout and their build side by side.
  4. Count the differences.
Every difference is a gap in your words — a bug you shipped. Fewest differences wins.

Now: what would you build?

Stay in your team. Go round — each person, 30 seconds:

  • Your name, program, and year
  • One thing on campus or in your life you'd build an app for, if building were easy

Your team picks its favourite to share with the room.

The semester, in plain words

  • Month 1 — learn to direct the AI safely. Starting today, with Git: your undo button for everything.
  • Month 2 — your team builds a real product and puts it on the internet.
  • Month 3 — you attack your own product: security, testing, load. AI-built software fails in predictable ways.
  • Final week — the plain-English feature test.

The one rule

You may use AI for everything.
You may hide behind it for nothing.

If you submit it, you can explain it, test it, and defend it.

Your AI log in the repo is where you show your thinking. It's graded as evidence of understanding — not of effort.

How you're graded

  • Weekly checkpoints — pass them by doing the lab and committing your work
  • Your team's project milestones
  • The final plain-English feature test
  • A written reflection at the end
No written exam. The way to do badly in this course is to be invisible in your own repository.

Next class — Git: the time machine.

Git

Your time machine

A repo is a photo album

Repository

The photo album of your project.

Commit

One photograph — the whole project frozen, with a caption saying what changed and why.

GitHub

The shared album in the cloud. Your teammates and instructors can see it.

Branch

A rough draft you photograph separately until it's ready for the main album.

Why this course needs the album

Your AI assistant edits fast and confidently — and sometimes wrongly.

The album lets you say two things:

  • "Show me exactly what you changed."  git diff
  • "Take me back to before you broke it."  git restore
Without the album, people keep five copies of their folder called final, final2, final-really — and the day the AI makes a mess, they lose work.

The ladder — by hand

# 1. First photograph
git init
git add .
git commit -m "first photo: working game"

# 2. Change something, then look before you commit
git diff
git add .
git commit -m "bugs speed up over time"

# 3. Break it on purpose — then rescue it
git restore game.js

# 4. Push to the shared album, see it on GitHub
git push          # first time: git push -u origin main

Step 3 is the one that converts people

Break the game. Watch it fail. Then bring it back with one command.

Feel the undo once, and you'll never keep a folder called final2 again.

Then: a draft, and a review

# 5. Work on a separate draft, then propose it
git switch -c feature/one-tweak
# ...make a change, commit...
git push -u origin feature/one-tweak
# open a Pull Request on GitHub
# your partner reviews it, leaves one comment, then merge
Stretch: ask the AI to make a commit for you — then read what it did. Your first taste of supervising an agent.

We did all of this by hand.
The AI can do it in seconds.
So why by hand?

You can't supervise what you can't do at walking pace.
