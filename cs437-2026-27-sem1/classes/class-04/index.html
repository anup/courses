Week 3 Lab

If It Isn’t Pushed, It Didn’t Happen

One job first: get last week’s work committed and pushed to your course repo — the one where Anup and Arjun are collaborators. Once your code is in, you move on. If you’re already there, you go further on the agent Arnav walked us through. Ask an instructor the moment you’re stuck.

Today’s One Rule: check in first

The whole class runs on one gate. Your work only counts when it is in the repo we can see. So before anything new, get your previous work pushed. Then — and only then — take the next step.

Track A — If you haven’t pushed yet

This is your day-one of actually using Git. Finish last week (the Bug Dodger game, your lab-notes/week-01.md, and the Class 3 Git steps), then check it in:

git status            # see what changed
git add .             # stage everything
git commit -m "week 01 + git catch-up"
git push              # send it to GitHub

If git push fails, it is almost always the plumbing, not you. Check these with an instructor:

  • git remote -v — is a remote set, pointing at your repo?
  • Are Anup and Arjun added as collaborators on the repo?
  • Is VS Code signed in to the correct GitHub account?

You are done when you can refresh your repo on GitHub and see your commit there.

Track B — If you’re already checked in

Continue on Arnav’s agent code (the lab repo he walked through). Work through module 03 — tool calling on your own machine; change it, break it, make it yours.

Put it in your repo the right way. Don’t scatter the files or drop them at the top level — that collides with your game and breaks the from common import … imports. Copy Arnav’s lab into one new folder, agent-lab/, keeping the modules and common/ together:

your-repo/
  games/week-01/        ← your game (already here)
  lab-notes/            ← your logs
  agent-lab/            ← NEW: Arnav's lab, all in one place
    common/             ← must stay a sibling of the modules
    01-llm-api-call/
    02-chat-history/
    03-tool-calling/    ← where you work today
    requirements.txt

Log what you did in lab-notes/week-03.md. Then the same gate applies: commit and push — git add . && git commit -m "agent-lab: module 03" && git push — before you pick a harder task below.

Harder Tasks (after you’ve checked in)

Each of these is harder work inside the same idea — the agent loop — not busywork:

  • Add your own tool. roll_dice(sides), get_time_in(city) — write the schema, write the function, register it, and watch the model discover and use it. This is the real test that you understand the harness.
  • A dangerous tool + a guardrail. Add delete_file, then make the loop ask for confirmation before it runs. (You’re previewing a real safety idea from later in the course.)
  • Use a branch. Do your new tool on a branch and open a pull request against main. (For this, your commit/push already needs to be smooth.)
  • Baby Claude Code. Add read_file, write_file, and run_bash tools, then ask the model about a file. Congratulations — that’s the same species of thing as the tools you use.

The Rule for AI Today: tutor, not typist

You may ask your AI assistant to explain any line — “what does this line do?” You may not ask it to write code for you today. The test: if what comes back is something you’d paste, you’ve crossed the line. Same tool, different mode — and learning to switch modes is itself part of this course.
