The whole idea, in one picture

Your work moves through four places. Each step has a name — that's the vocabulary.

Working folder

The files you're editing right now.

↓  stage  (git add)

Staging area

The changes you've picked to go into the next checkpoint.

↓  commit  (git commit)

Local history

Your saved checkpoints, on your laptop.

↓  push  (git push)

GitHub

The shared copy in the cloud — teammates and instructors can see it.

Staging is the only strange one: it's you choosing which changes go into the next checkpoint. Everything else is just save (commit) and share (push).

Three more things you can ask for

See what changed

"What did you change since my last checkpoint?"

git diff

Rewind

"Take me back to the last working checkpoint."

git restore

A safe parallel try

Experiment on a branch without touching the working version.

git branch

These are concepts, not spells to memorize. Know they exist and what they're for — that's enough to ask for them.

Why bother with a branch?

A branch is a safe parallel copy of your code. Two reasons you'll reach for one:

  • Let the AI attempt something big — a whole start screen, a new level, a refactor — on a branch. If it turns into a mess, delete the branch; your working game never knew. If it's good, merge it.
  • Work alongside a teammate — you each take a branch, change the same game at once, and merge without overwriting each other.
main stays working and demo-ready. The risk lives on the branch.

You didn't memorize commands. You asked.

Everything today, you did two easy ways — no terminal gymnastics:

  • VS Code's Source Control panel — stage, message, commit, push, with buttons.
  • Copilot / the agent — just say what you want:
"Commit this with a clear message." · "What did you change?" · "Undo the last change." · "Put this on a branch called login." · "Push it to GitHub."
You supply the intent; the tool runs the Git. The whole skill is knowing what to ask for — which is the handful of ideas above.

Five commands. Infinite Git.

These five cover almost everything you'll do this semester:

status  ·  add  ·  commit  ·  push  ·  restore

Past them are hundreds more and endless situations — merges, conflicts, rebases, rewritten history.

You don't memorize that. Learn the ideas, recognize the words, and ask the AI for the rest. That's Git the easy way.
