Why Git — and why this course can't run without it

You're about to let an AI edit your code: fast, confident, and sometimes wrong.

  • You need a known-good checkpoint to fall back to — saved before you let it touch anything.
  • You need to see exactly what it changed, line by line, before you trust it.
  • And a team needs to work on one codebase without overwriting each other.
Without it, people keep folders called final, final2, final-really — and the day the AI makes a mess, they can't get back.

The whole idea, in one picture

Your work moves through four places. Each step has a name — that's the vocabulary.

Working folder

The files you're editing right now.

↓  stage  (git add)

Staging area

The changes you've picked to go into the next checkpoint.

↓  commit  (git commit)

Local history

Your saved checkpoints, on your laptop.

↓  push  (git push)

GitHub

The shared copy in the cloud — teammates and instructors can see it.

Staging is the only strange one: it's you choosing which changes go into the next checkpoint. Everything else is just save (commit) and share (push).

Three more things you can ask for

See what changed

"What did you change since my last checkpoint?"

git diff

Rewind

"Take me back to the last working checkpoint."

git restore

A safe parallel try

Experiment on a branch without touching the working version — keep it or throw it away.

git branch

These are concepts, not spells to memorize. Know they exist and what they're for — that's enough to ask for them.

You won't memorize commands. You'll ask.

In this course you drive Git two easy ways — no terminal gymnastics required:

  • VS Code's Source Control panel — stage, write a message, commit, and push with buttons.
  • Copilot / the agent — just say what you want:
"Commit this with a clear message." · "What did you change?" · "Undo the last change." · "Put this on a branch called login." · "Push it to GitHub."
You supply the intent; the tool runs the Git. The whole skill is knowing what to ask for — which is exactly the handful of concepts you just saw.

The one that converts people

Break your Bug Dodger on purpose. Watch it fail. Then bring it back — you're one checkpoint away.

Feel the rewind once, and you'll never keep a folder called final2 again.

A commit is a checkpoint with a caption

Whether you or the AI writes it, a checkpoint needs a caption that says what changed and why — short, present tense.

Good
add score counter
fix crash when list is empty
Useless
stuff · final · final2 · asdf
If the agent writes "update code," tell it to do better. The captions are how you find the checkpoint to rewind to.

Working together: branches and reviews

  • Each person works on their own branch — a safe parallel copy of the code.
  • When it's ready, open a Pull Request on GitHub: your teammate reads the change and comments before it joins the main version.
Ask Copilot to make the branch and open the PR. Your real job is the review — reading what changed and deciding if it's good. That's the whole course in miniature.

Five commands. Infinite Git.

These five cover almost everything you'll do this semester:

status  ·  add  ·  commit  ·  push  ·  restore

Past them are hundreds more commands and endless situations — merges, conflicts, rebases, rewritten history.

You don't memorize that. Learn the ideas, recognize the words, and ask the AI for the rest. That's Git the easy way.
