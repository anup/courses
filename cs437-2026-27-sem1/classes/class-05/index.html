Track B — Make the harness harder

You have module 03 (tool calling) running, and maybe your own first tool. Each rung below is harder work inside the same idea — the agent loop. Pick one, build it, then commit and push before you start the next. They roughly build on each other, but you don’t have to do them in order.

  1. Give it a personality. Control the agent’s behaviour with a system prompt.
    • Prepend a system message to the conversation your loop sends.
    • Write two personas and try both on the same question — e.g. a terse senior engineer (answers in two sentences, no fluff) versus a Socratic tutor (only asks questions, never hands over code).
    • Done when the same model visibly behaves differently depending on the prompt. That prompt is your steering wheel.
  2. Make it count. Surface token usage live (module 01 already reads it — now show it every turn).
    • Read the usage field on each API response.
    • After every turn, print input tokens, output tokens, and a running session total.
    • Done when you can watch the total climb as the conversation grows — you can now see what context costs.
  3. Keep it in budget. Stop the context from growing forever (builds on the step above).
    • Pick a budget — say 4,000 tokens.
    • When the running total crosses it, drop or summarise the oldest turns before the next call.
    • Done when a long conversation keeps working instead of erroring or ballooning in cost.
  4. Grow and chain tools. Module 03 ships time/weather; add your own and let the model combine them.
    • Add two tools with proper schemas — e.g. calculator(expression) and read_file(path).
    • In the loop, let the model call one tool, feed the result back, then call another before it answers.
    • Done when the model makes two or more tool calls in a single turn to reach an answer.
  5. Guardrail the dangerous ones. Not every tool should run unchecked.
    • For any tool that changes state (write_file, run_bash), pause the loop and ask the user to confirm before running it; abort cleanly on “no.”
    • Done when the agent asks before it writes or runs anything, and respects the answer. You’re previewing a real safety idea from later in the course.
  6. Baby Claude Code. Three tools together make a tiny coding agent.
    • Wire up read_file, write_file, and run_bash (keep the guardrail on the last two).
    • Ask it “what does game.js do?” and let it read; then ask it to add a comment and let it write.
    • Done when it can inspect and edit a real file in your repo through the loop — the same species of thing as the tools you use every day.

Branching and project teams come next — we’ll form teams first, then learn branching together, so hold off on making it a whole-room thing today. If you want to branch now, treat it as a personal stretch: do one rung above on a branch and open a pull request against main.

The rule for AI today: tutor, not typist

You may ask your AI assistant to explain any line — “what does this do?” You may not ask it to write the code for you. The test: if what comes back is something you’d paste, you’ve crossed the line. Same tool, different mode — switching modes is part of the course.
