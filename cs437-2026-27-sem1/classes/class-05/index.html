Track B — Make the harness harder

You have module 03 running and maybe your own first tool. Go further — each step is harder work inside the same idea, the agent loop. Do one, commit and push, then take the next.

  • Give it a personality. Add a system prompt you control. Make it a terse senior engineer, or a Socratic tutor that refuses to hand over code. Swap personas and watch the behaviour change — the system prompt is the steering wheel.
  • Make it count. Print token usage each turn — input, output, and a running session total (from the API response’s usage). Now you can see what context costs.
  • Keep it in budget. When the running total crosses a threshold, trim or summarise old history so the agent keeps working. This is real context management. (Builds on the step above.)
  • Grow and chain tools. Add two of your own — e.g. calculator, read_file, write_file — and let the model chain them in the loop: call one, use the result, call the next.
  • Guardrail the dangerous ones. Any tool that changes state (write_file, run_bash) asks for confirmation before it runs. You are previewing a real safety idea from later in the course.
  • Baby Claude Code. With read_file, write_file, and run_bash wired up, ask the model about a file in your repo. That is the same species of thing as the tools you use every day.

Branching and project teams are coming next — we will form teams first, then learn branching together. Not today. If you want to branch now, treat it as a personal stretch (do a step above on a branch and open a PR), not something the whole room does yet.

The rule for AI today: tutor, not typist

You may ask your AI assistant to explain any line — “what does this do?” You may not ask it to write the code for you. The test: if what comes back is something you’d paste, you’ve crossed the line. Same tool, different mode — switching modes is part of the course.
