Queues Class 12

  • 1700. Number of Students Unable to Eat Lunch — a queue of students against a stack of sandwiches.
  • 232. Implement Queue using Stacks — two stacks, one per end.
  • 225. Implement Stack using Queues — the reverse: which operation has to become slow?
  • 622. Design Circular Queue — the array queue, with wrap-around.

Dynamic memory — malloc and free Class 08 Class 09

Most array problems hand you the array and ask you to change it in place, so you never allocate anything. The ones below are different: they ask you to return something, and in C that means you have to make it yourself. LeetCode says so in the stub it gives you — "the returned array must be malloced, assume caller calls free()". Every problem here is a malloc exercise wearing an array problem as a disguise.

One warning before you start. The judge checks your answer, not how you produced it — so static int result[1000]; return result; also passes, and you will find people doing it. Do not. A static array is one shared buffer for every call, so the moment anything calls your function twice the first answer is gone; and calling free() on it, which the stub says the caller will do, is undefined behaviour. It passes the judge and is wrong in real code. Allocate properly.

Two rules that catch everyone at first. You must set *returnSize as well as returning the pointer, because a pointer carries no length — that is the same fact from Class 08, now enforced by a judge. And the judge frees what you return; anything else you allocate along the way is yours to free.

Start here — one array in, one array out.

  • 1929. Concatenation of Array — the smallest version of the whole pattern: allocate 2n ints, fill it, set *returnSize. Nothing else to think about. Start here.
  • 977. Squares of a Sorted Array — allocate n, then fill it from the back with two pointers.
  • 66. Plus One — the answer is sometimes longer than the input (999 becomes 1000), so you cannot reuse the array you were given. Decide the size before you allocate.
  • 448. Find All Numbers Disappeared in an Array — you do not know how big the answer is until you have counted. Either count first and allocate exactly, or allocate the worst case and report the real size.
  • 238. Product of Array Except Self — allocate the answer, then two passes over it.

Then — an array of arrays.

  • 118. Pascal's Triangle — the real test. The signature is int** generate(int numRows, int* returnSize, int** returnColumnSizes), which needs three separate allocations: the outer array of row pointers, each row, and the array holding every row's length. Draw the picture before you write it.
  • 54. Spiral Matrix — a 2D array in, one flat allocated array out.

Finally — allocating nodes, not arrays. These two carry no note in the stub, because nothing is being returned as an array — but you cannot produce the answer without allocating, so the obligation is the same.

  • 2. Add Two Numbers — the linked-list problem where the judge does not hand you the answer's memory. You malloc a node per digit, carry included. This is the exercise from Class 10 with a judge attached.
  • 707. Design Linked List — build the whole structure yourself: add, get, delete. Every malloc needs its matching free, and here you are the one who has to remember.

A warning about the rest of the linked-list set on this page: the judge builds those lists for you, so they exercise pointer manipulation but never allocation. That is why the two problems above are listed separately — and why the write-it-yourself exercises on the Class 10 page still matter.

Structures Class 09

No judge for these — they are short C programs. A struct behaves exactly like any other value: pass it by value and it is copied, pass its address and the function sees the original.

  • The employee record exercise from class: 0 <name> adds, 1 <index> removes, -1 ends. Reuse add and removeAt with struct Person in place of int.
  • void birthday(struct Person *p) — add a year. Write the by-value version too, and confirm it does nothing.
  • Print sizeof(struct Person) and compare it with the sum of its fields. Any difference is padding.
  • struct Person *highest_paid(struct Person *arr, int n) — return a pointer into the array, then modify through it.
  • Sort an array of structs by salary, reusing any sort from Classes 03–06. Only the comparison changes.
  • Swap char name[50] for char *name. What has to change when you add a person, and when you remove one?

Pointers & memory Class 08 Class 09

Two pointers walking an array, functions that write through a pointer, and memory whose lifetime you manage yourself. Write these in C with pointers rather than indices — the point is fluency with *p, p++, and left < right.

  • 344. Reverse String — two pointers from opposite ends, swapping inward.
  • 125. Valid Palindrome — the same walk, comparing instead of swapping.
  • 167. Two Sum II — ends inward on a sorted array.
  • 283. Move Zeroes — read and write pointers moving at different speeds.
  • 26. Remove Duplicates from Sorted Array — one reads, one writes.
  • 27. Remove Element — copy and skip, in place.
  • 189. Rotate Array — in place via three reversals.
  • 88. Merge Sorted Array — merge backwards into the spare room.
  • 11. Container With Most Water — harder: why is moving the shorter side safe?

Alongside these, write the C exercises on the Class 09 page: reverse, add, removeAt, and the unknown-length input loop. They are where malloc and free actually get practised.

Sorting at the Ω(n log n) bound Class 07

Comparison-based sorting cannot beat Ω(n log n), so these problems live right at it: sort (sometimes with your own comparator), then sweep. The sort is the dominant cost.

  • 2418. Sort the People — warm-up: sort one array by another, with a custom comparator.
  • 179. Largest Number — define the comparison (compare concatenations); any comparison sort does the rest.
  • 56. Merge Intervals — sort by start, then one sweep.
  • 435. Non-overlapping Intervals — sort by end time, then greedily keep what fits.
  • 452. Minimum Number of Arrows to Burst Balloons — the same sort-by-end recipe as 435, dressed up.

Beating the bound: counting sort Class 07 Optional

We have not taught counting sort in class yet, so none of this is expected of you — it is optional, for the curious. The lower bound only binds algorithms that compare, and these problems beat it by not comparing: when keys are bounded integers, count them instead.

  • 75. Sort Colors — three possible values: count and rewrite in O(n), no comparisons.
  • 912. Sort an Array — values fit in a fixed range; submit counting sort this time.
  • 1122. Relative Sort Array — values at most 1000; one counting array does it all.
  • 274. H-Index — bucket by citation count for O(n) instead of sorting.
  • 164. Maximum Gap — hard: linear time via buckets, despite looking like it needs a full sort.
