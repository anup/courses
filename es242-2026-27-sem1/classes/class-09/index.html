Structures

An employee has a name, an age, and a salary. Three parallel arrays would work and would be miserable to keep in step, so C lets you glue the three fields into one type: struct Person. Everything from the last class then applies unchanged. Pass a struct by value and it is copied, all fifty-eight bytes of it, and the function cannot change the original — so you pass &p1 instead and reach the fields through p->name. Return a local struct and you hit the same lifetime problem as returning a local array, with the same fix. Put structs in a heap array that grows and shrinks, and you have a record system.

The thread through the slides

  • Declaring and filling one — struct Person p1 = {"Ria", 25, 10000}; at declaration, or field by field afterwards. Note that p2.name = "Rahul" does not compile: name is a char array, so it needs strcpy.
  • Passing by value copies the whole struct — print(p1) duplicates every field, and changes inside the function do not reach main. Exactly the behaviour from Class 08, just with a bigger thing being copied.
  • Passing a pointer — print(&p1) with a struct Person *p parameter. Now the function sees the original.
  • The arrow — p->name is shorthand for (*p).name. You need it because . binds tighter than *, so *p.name parses the wrong way.
  • Returning a struct — returning by value copies; returning a pointer to a local is the dangling-pointer bug again. malloc(sizeof(struct Person)) is the fix.
  • Arrays of structs — a heap array of struct Person, grown and shrunk with the add and removeAt patterns from Class 08.

Practice — the employee record exercise

The main exercise from class. Input is a series of commands, one per line, ending at -1: 0 <name> adds a person to the record, 1 <index> removes the person at that index. The record is a dynamically sized array of structures.

  • Build it with the add and removeAt functions from Class 08, changed from int to struct Person. Almost nothing else changes — that is the point.
  • Print the record after every command so you can see it working.
  • Handle the cases the happy path ignores: removing from an empty record, and an index that is out of range.
  • Check that every malloc is matched by exactly one free. On macOS, leaks -atExit -- ./a.out will tell you.

Practice — structs and pointers together

No judge for these; they are short C programs. Full topic list on the practice page.

  • Write void birthday(struct Person *p) that adds 1 to the person's age. Then write the by-value version and confirm it does nothing.
  • Print sizeof(struct Person) and compare it with the sum of its fields. If it is larger, the compiler has inserted padding to keep fields aligned.
  • Write struct Person *highest_paid(struct Person *arr, int n) returning a pointer into the array, not a copy. Then change the salary through that pointer and confirm the array changed.
  • Sort an array of struct Person by salary, reusing any sort from Classes 03–06. Only the comparison changes — the algorithm does not care what it is moving.
  • Give struct Person a char *name instead of a char name[50]. What now has to happen when you create a person, and what has to happen when you remove one?
