Arrays, Pointers & Structures

A second pass over pointers, starting from a question about an ordinary function: when sum(a, b) runs, does it get a and b, or copies of them? Copies — which is why a function cannot change its caller's variable, and why scanf has always needed &a instead. Arrays break the pattern: pass one to a function and nothing is copied at all, because what the function receives is a pointer to the first element. That single fact explains why int A[] and int *A mean the same thing in a parameter list, and why a function can quietly rewrite your array. The class then moves to memory you manage yourself — malloc, free, and an array whose size you do not know until the input arrives — and finishes by gluing several fields into one type, struct Person, which is what the next class needs to build a list.

The thread through the slides — arrays and pointers

The deck builds one idea at a time, each slide answering the question the previous one raised:

  • Pass by value — sum(a, b) gets copies, so the parameters are not the caller's variables. scanf needs &a precisely because it has to write back.
  • Arrays are the exception — sum(num, 5) copies nothing. A is a pointer to num[0], so the function reads your array directly, and a pointer carries no length, hence the separate n.
  • Four ways to write the same function — int A[] or int *A in the signature, A[i] or *(A+i) in the body. All four compile to the same thing.
  • Reverse with two pointers — left and right start at the ends and walk inward, swapping. Because the array arrived as a pointer, the swaps land in the caller's array.
  • Returning an array — the create() that returns a local array is broken: num dies when create returns. malloc fixes it, and the caller then owes a free.
  • Growing an array — add() allocates one slot bigger, copies, appends. In a loop, that reads input of unknown length.

The thread through the slides — structures

An employee has a name, an age, and a salary. Three parallel arrays would work and would be miserable to keep in step, so C lets you glue the fields into one type. Everything above then applies unchanged.

  • Declaring and filling one — struct Person p1 = {"Ria", 25, 10000}; at declaration, or field by field afterwards. Note that p2.name = "Rahul" does not compile: name is a char array, so it needs strcpy.
  • Passing by value copies the whole struct — print(p1) duplicates every field, and changes inside the function do not reach main. The same rule as above, just with a bigger thing being copied.
  • Passing a pointer — print(&p1) with a struct Person *p parameter. Now the function sees the original.
  • The arrow — p->name is shorthand for (*p).name. You need it because . binds tighter than *, so *p.name parses the wrong way.
  • Returning a struct — returning by value copies; returning a pointer to a local is the dangling-pointer bug again. malloc(sizeof(struct Person)) is the fix.
  • Arrays of structs — a heap array of struct Person, grown and shrunk with the same add and removeAt patterns.

Practice — the exercises from the slides

These are the problems posed in class. No judge — write them, run them, and make sure every malloc has exactly one free.

  • void reverse(int *A, int n) — reverse in place with two pointers. Check that main's array actually changed.
  • int *add(int A[], int n, int num) — return a new array one longer, with num appended. The original must be untouched.
  • Read positive integers until -1, one per line, and print them in reverse. You do not know how many are coming, so grow the array with add as you go. Mind the order inside the loop: allocate the new block, then free the old one, then reassign.
  • int *removeAt(int *arr, int n, int index) — return a new array with that element gone. Two pointers walk in step; on the removed index only the source advances.
  • Count the element copies your input loop performs for 1000 numbers. About 500,000 — the cost of growing by one each time, and the reason real implementations double instead.

Practice — the employee record exercise

The structures exercise from class. Input is a series of commands, one per line, ending at -1: 0 <name> adds a person to the record, 1 <index> removes the person at that index. The record is a dynamically sized array of structures.

  • Build it with the add and removeAt functions above, changed from int to struct Person. Almost nothing else changes — that is the point.
  • Print the record after every command so you can see it working.
  • Handle the cases the happy path ignores: removing from an empty record, and an index that is out of range.
  • Check that every malloc is matched by exactly one free. On macOS, leaks -atExit -- ./a.out will tell you.
