Lower Bounds on Comparison-Based Sorting

Merge sort, heap sort, and quick sort all land at O(n log n). Can any comparison-based sort do better? No — and we can prove it for every such algorithm at once. Model the algorithm as a binary execution tree: each comparison branches two ways, and each of the n! input orders must reach its own leaf. A binary tree with n! leaves has height at least log₂(n!) = Ω(n log n), so some input forces that many comparisons. The escape hatch: stop comparing. When keys are small integers, counting them sorts in O(n).

Practice — sorting at the bound

The theorem says Ω(n log n) is the floor for comparison-based sorting — these problems live right at it. Each one is sort-then-sweep: the sort is the dominant cost, and in the comparison model you cannot do better. In the first two, you define the comparison yourself. Full topic list on the practice page.

  • 2418. Sort the People — warm-up: sort one array by the values of another, with a custom comparator.
  • 179. Largest Number — the comparison model in action: decide when a comes before b (compare the two concatenations), and any comparison sort does the rest.
  • 56. Merge Intervals — sort by start, then one sweep; the O(n log n) sort is the whole cost.
  • 435. Non-overlapping Intervals — sort by end time, then greedily keep what fits.
  • 452. Minimum Number of Arrows to Burst Balloons — the same sort-by-end recipe as 435, dressed up.
  • Revisit 217. Contains Duplicate from Class 01: the hash-set solution runs in O(n). Why does that not contradict today's theorem? (A hash lookup is not a comparison — the bound only governs the comparison model.)
  • Paper exercise: draw the complete execution tree for sorting three numbers a, b, c. Check it has 3! = 6 leaves and height 3 — matching ⌈log₂ 6⌉ — so 3 comparisons are unavoidable in the worst case.

Practice — beating the bound (optional)

A heads-up before you start: we have not taught these techniques in class yet, and none of this is expected of you. It is here for the curious — a look at what lies just past the lecture. The bound only binds algorithms that compare, and every problem below dodges it by not comparing: whenever the keys are bounded integers, count them instead. More on the practice page.

  • 75. Sort Colors — only three possible values: count them and rewrite the array in O(n). Compare with your partition solution from Class 05.
  • 912. Sort an Array — values fit in a fixed range; write counting sort and beat your earlier O(n log n) submissions.
  • 1122. Relative Sort Array — values at most 1000; one counting array handles both the given order and the leftover tail.
  • 274. H-Index — bucket papers by citation count for O(n), where sorting first costs O(n log n).
  • 164. Maximum Gap — hard: linear time via buckets, even though it looks like it needs a full sort.
