Linked Lists

The dynamic array from Class 09 could grow, but every insertion copied the whole thing. The cost is structural: an array's elements must sit next to each other in memory, so making room means moving everything. Give up that requirement and the problem disappears. Let each element carry the address of the next one, and inserting at the front costs one malloc and one assignment — O(1), no matter how long the list is. The bill arrives elsewhere. There is no arithmetic that jumps to element i any more, so reaching it means following i pointers from the head, and search becomes a walk. Two data structures, the same operations, opposite cost profiles — that trade is the whole lesson.

The thread through the slides

  • Why bother — the deck opens and closes with the same comparison table. Array: insert O(n), get the i-th O(1). List: insert O(1), get the i-th O(i). Neither wins outright.
  • The node — struct record { int num; struct record *next; };. A structure containing a pointer to its own type, which is legal precisely because a pointer has a fixed size.
  • The head — the list is nothing more than a pointer to its first node. An empty list is head == NULL, and the last node's next is NULL, which is what stops every loop.
  • Printing — while (head != NULL) { printf(...); head = head->next; }. Moving the local head is safe because it is a copy, so the caller's head is untouched. That is the pass-by-value rule from Class 09 working in your favour.
  • Adding at the front — allocate the node, point its next at the current head, then make it the new head. Order matters: reassign head first and you have lost the rest of the list. It returns the new head, which is why callers write head = add(head, 3);.
  • Deleting — two pointers again, but this time p walks ahead and q trails one behind, because unlinking a node means writing to the node before it. Then free(p).

The cases delete has to handle

The slides ask you to think about all of them. Work these out on paper before you write the code — each one breaks a different assumption in the simple version.

  • The value is not in the list at all. p reaches NULL; do not dereference it.
  • The value is in the first node. q is still NULL, so there is no q->next to update — the head itself has to move.
  • The list is empty to begin with.
  • The list has exactly one node, and it is the one being deleted.
  • The value appears more than once. The slides delete only the first; decide what your version does.

Practice — writing the list yourself

In C, from scratch, with malloc and free. These come before the LeetCode problems — the judge hands you a list already built, so it skips the part you most need to practise.

  • Write add, printList and delete from the slides, driven by a main that reads commands until -1.
  • Write freeList(struct record *head). Careful: you cannot free(p) and then read p->next, so save the next pointer before freeing.
  • Write int length(struct record *head) and struct record *find(struct record *head, int num), returning NULL when it is absent.
  • Write append, which adds to the end instead of the front. Why is this O(n) when add was O(1), and what would you store to make it O(1)?
  • Build a list of 10,000 elements, then time reading the 9,000th against the same read on an array. The table on slide 1 should stop being abstract.

Practice — linked list problems

Once your own list works, these drill the pointer manipulation. Full topic list on the practice page.

  • 206. Reverse Linked List — the essential one. Three pointers: previous, current, next. Draw it before you write it.
  • 876. Middle of the Linked List — two pointers at different speeds; the fast one moves two nodes per step.
  • 203. Remove Linked List Elements — the delete from class, applied to every match instead of the first.
  • 21. Merge Two Sorted Lists — the merge step of merge sort from Class 04, relinking nodes rather than copying values.
  • 141. Linked List Cycle — the same fast and slow pointers as 876. If they ever meet, the list loops.
  • 19. Remove Nth Node From End of List — start one pointer n nodes ahead, then move both until it falls off the end.
  • 234. Palindrome Linked List — harder: find the middle, reverse the second half, compare. Three of the problems above, combined.
