Linked Lists

The dynamic array from Class 09 could grow, but every insertion copied the whole thing. The cost is structural: an array's elements must sit next to each other, so making room means moving everything. Give that up — let each element carry the address of the next — and inserting at the front costs one malloc and one assignment, no matter how long the list is. The bill arrives elsewhere. Nothing jumps to element i any more, so reaching it means following i pointers. Same operations, opposite cost profiles: that trade is the lesson.

What the class covered

  • Why bother — array: insert O(n), get the i-th O(1). List: insert O(1), get the i-th O(i). Neither wins outright.
  • The node — struct record { int num; struct record *next; };, a structure holding a pointer to its own type, which is legal because a pointer has a fixed size.
  • The head — the list is just a pointer to the first node. Empty is head == NULL; the last node's next is NULL, which stops every loop.
  • Printing — moving the local head is safe because it is a copy. The pass-by-value rule working in your favour.
  • Adding at the front — allocate, point the new node's next at the head, then move the head. Reassign the head first and you lose the list.
  • Deleting — p walks ahead and q trails behind, because unlinking means writing to the node before. Then free(p).

Work the delete cases out on paper before coding — each breaks a different assumption: the value is absent; it is in the first node (q is still NULL); the list is empty; the list has one node; the value appears twice.

Practice

Write the list yourself first, in C with malloc and free. The judge hands you a list already built, so it skips the part you most need to practise.

  • add, printList and delete from the slides, driven by a main that reads commands until -1.
  • freeList — save the next pointer before freeing, or you read memory you just gave back.
  • append, adding at the end. Why is it O(n) when add was O(1), and what would you store to fix that?

Then the judge — this is where pointer manipulation really gets tested. Full list on the practice page.

  • 206. Reverse Linked List — the essential one. Three pointers: previous, current, next. Draw it first.
  • 876. Middle of the Linked List — two pointers, the fast one moving two nodes a step.
  • 203. Remove Linked List Elements — the class delete, applied to every match.
  • 21. Merge Two Sorted Lists — merge sort's merge step from Class 04, relinking rather than copying.
  • 141. Linked List Cycle — fast and slow again; if they meet, it loops.
  • 234. Palindrome Linked List — harder: middle, reverse, compare. Three of the above combined.
