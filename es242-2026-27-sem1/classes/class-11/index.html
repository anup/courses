Stacks

A compiler has to check that every ( and { in your program is closed, and closed in the right order. The first algorithm the class wrote finds the first closing bracket, walks left to its partner, deletes both, and repeats. It works, but every walk left passes over brackets already deleted, and that costs O(n2). The fix is to keep the unmatched opening brackets somewhere, with the latest one on top. A closing bracket then needs to look in one place only. That place is a stack, and it brings the check down to O(n).

What the class covered

  • Balanced brackets — every opening bracket has a closing partner, and pairs nest properly. {()} is balanced; (){)}} and ((}{)) are not.
  • The slow version — find the first closing bracket, match it with the nearest undeleted bracket to its left, delete both, repeat. Walking over deleted brackets makes it O(n2).
  • The stack idea — push opening brackets. When a closing bracket arrives, its partner must be on top. Pop it and compare.
  • Two operations — push puts an element on top; pop removes the top element and returns it. Both are O(1).
  • Stack in an array — the array plus an index top that starts at -1. push and pop change top through a pointer, int *ptop, so the caller sees the change. Push onto a full stack or pop from an empty one and the program stops.
  • The full checker — read the string once. The answer is 0 in three cases: a closing bracket finds the stack empty, it pops the wrong kind of opening bracket, or the string ends with brackets still on the stack. Otherwise print 1. O(n).
  • Stack in a linked list — when the maximum size is not known in advance, push is Class 10's add-at-the-front, and pop removes the head node and frees it. Still O(1) each, with no size limit.

Before you trust your checker, run it on these by hand: "", "(", ")", "(()", "())", "({)}". Each one breaks a different line of the code.

Practice

Write both stacks in C first: the array version with top, then the linked-list version. Solve the problems below with a stack you wrote yourself.

  • The balanced-bracket checker from the slides. Extend it to [ and ], and make it print the position of the first bracket that breaks the balance.
  • Reverse a string with a stack: push every character, then pop them all.
  • Remove the exit calls from pop. How can the caller tell that the stack was empty when the return type is char?
